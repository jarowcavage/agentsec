Connect draft pull requests

Public repository scanning does not need a token. Publishing a reviewed change does.

  1. Create a fine-grained GitHub token limited to a disposable repository you control. Give it Contents and Pull requests read/write permissions.
  2. Set AGENTSEC_GITHUB_REPOSITORIES to a comma-separated list of owner/repository targets and AGENTSEC_GITHUB_TOKEN to that token in the server’s ignored .env file. Never paste the token into a repository URL.
  3. Set AGENTSEC_APPROVER_PASSWORD to a separate password of at least 16 characters. Restart the local server after loading these environment settings.
  4. Scan that repository, prepare a supported file change, and review it as the local approver. Approve the exact proposal.
  5. Enter the separate approver password and click Create draft pull request on GitHub. This creates a branch and draft PR; nothing is merged.

If the default branch changed since scanning, scan again. If a write’s result is uncertain, inspect GitHub before retrying; automatic retries are blocked to avoid duplicates.

Automatic file changes support simple Python requirements pins and exact npm versions in package.json when no npm lockfile is present. npm lockfile changes still require a developer action plan. Neither path runs arbitrary repository tests.

Local role selection is for a single-user demonstration. This is not production authentication.
