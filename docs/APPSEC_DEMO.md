# Application security narrative

Discovery: which findings consume the most investigation effort, what evidence makes recommendations actionable, and how do developers receive remediation work?

Choose Application security. Run the offline scenario, inspect the package and supporting excerpts, explain unknown reachability and review the proposed issue. The live workbench preserves CycloneDX upload, exact package matching through OSV, direct/transitive dependency context, advisory severity data where present, fixed candidates and structured OpenAI recommendations. Exact citations establish provenance, not semantic correctness or reachability.

Request temporary action access and demonstrate the approved local issue. Optional GitHub creation is separately configured, explicitly approved and never an automatic demo fallback. Explain how this connects validated evidence with developer coordination while retaining human accountability.

Use the measured counts and timings to discuss a pilot, then change ROI assumptions with the buyer. Do not equate workflow-stage latency with total engineer effort. This is not Semgrep SAST, code scanning or a Semgrep integration. It does not prove that a suggested version is compatible with the application.
