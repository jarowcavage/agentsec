# Demo runbook

## Install and launch

From the repository root, use Python 3.12 or newer:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
AGENTSEC_DEMO=1 uvicorn agentsec.main:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000/console. No external credentials are needed for the synthetic demo. Use one worker. The main database defaults to `.agentsec/workbench.db`; interview data is in `.agentsec/workbench.demo.db`. Both are ignored by Git. Login sessions are in memory and expire after one hour or on restart.

Choose Security Administrator, Switch persona, Reset Demo and confirm. This populates synthetic identities and clears only demo data. Switch to Security Analyst and follow [DEMO_SCRIPT.md](DEMO_SCRIPT.md). The run action creates a real local scan/recommendation using fixture providers. It does not create a pending approval until you click Request temporary issue permission.

## Tests

```sh
ruff check .
ruff format --check .
node --check agentsec/static/console.js
python -m pytest -q -m 'not live and not browser'
python -m playwright install chromium
AGENTSEC_BROWSER=1 python -m pytest -q -m browser
python scripts/security_report.py
```

Set `AGENTSEC_CHROMIUM` to an installed Chromium/Chrome executable if needed. Security report results are generated by executing tests, then shown in Overview. This is synthetic evaluation, not a production assurance claim. `scripts/evaluate.py` also runs the original 28 AppSec fixtures. Live OSV/OpenAI tests remain explicit opt-ins documented in README.

## Optional connected GitHub

Keep the app on loopback. Set `AGENTSEC_GITHUB_REPOSITORY` to one explicitly approved disposable test repository; set `AGENTSEC_GITHUB_TOKEN` to a fine-grained token restricted to that repository with Issues write permission. Set `AGENTSEC_APPROVER_PASSWORD` to a unique strong password at least 16 characters long. Do not commit these values. Load them into the server environment and restart. No credentials are generated or stored in the UI.

Generate a live validated recommendation in the original workbench. The scan ID is in its URL fragment; select its finding ID from the API response if needed. In Connected GitHub, enter the separate administrator password and scan/finding IDs. Request real issue permission, load requests, inspect exact content and repository, approve, then explicitly create. Demo persona cookies alone cannot approve a real write. GitHub uses the [official issue endpoint](https://docs.github.com/en/rest/issues/issues#create-an-issue).

A request is deduplicated by repository and title, expires, and is claimed before the network write. An uncertain response is terminal for automatic execution: inspect the target repository manually. Do not delete the database to retry a possibly successful write. A reset never touches connected requests. This prototype does not globally deduplicate issues created by other tools.

## Troubleshooting and fallback

- Connection refused: start Uvicorn with the command above; do not assume an old terminal session survives.
- Persona switching disabled: launch with `AGENTSEC_DEMO=1`. Do not expose this mode to other users.
- Administrator required: switch the local demo persona. Connected mode separately requires the configured password.
- Suspended/revoked demo agent: Reset Demo as administrator; live agent permissions are unaffected.
- Fixture investigation failure: inspect Audit explorer; MCP must be able to start the same Python interpreter.
- OpenAI/OSV unavailable: use the explicitly labeled offline scenario. No silent fallback is performed.
- GitHub timeout: the request becomes uncertain and cannot be retried automatically.
- Docker permission denied: use native Python. Docker verification can run in CI; never change another user's socket permissions.

For Compose, set `AGENTSEC_DEMO=1 docker compose up -d --build --wait`. The app binds its published port to loopback. Hosted application deployment remains deferred by user instruction.
